# Codex Pocket 0.7.0 候选交付说明

本文件随候选包交付。构建身份、实际验收结果和校验和以同目录的构建清单与验收记录为准。

## 本次变化

- 手机发送：初始化通知缺失时，以同一连接上初始化后的原生 RPC 成功作为就绪证据；主桌面、浏览器辅助运行时和 CLI 分开处理。重连和返回前台刷新会话归属、运行时和权限；过时响应不覆盖新状态。
- 桌面：托盘助手与“概览、设备与连接、更新与修复、设置”管理页。关闭窗口保留托盘；退出界面、暂停远程和停止后台是不同操作。诊断读取正在运行的后台，显示时间、版本与构建身份。
- 更新：校验 Ed25519 签名和完整文件清单后暂存，等待任务空闲，再通过写入围栏、检查点和版本交接切换。正在运行、等待回答或结果未知的工作会阻止切换。
- 用量：只读 CC Switch，按结构兼容 schema 24、25、26。默认最近七个上海自然日、Codex 代理请求；七指标、真实趋势、上游／模型／对话分组与分页明细。未记录或不可计算的指标保持缺失。
- 助理：对话为主，保留任务、定时、记忆入口；启动分为运行时、账户来源、原生能力、协调会话。协调器可通过有类型的工具管理定时和记忆；执行子任务没有这些私有写权限。未知操作核对原回执，不再次派发。

## 升级与数据迁移

1. Windows 与 Android 使用同一份候选构建编号。保留当前完整安装和数据，不手动删除旧进程文件、配对或助理状态。
2. Android 使用原发布证书签名，直接覆盖安装；卸载会删除本地数据，因此不使用卸载再安装作为升级流程。
3. Windows 更新沿用用户 SID、程序路径、进程创建时间和构建身份核验。出现跨账户、目录重定向、文件占用或证据不足时保留原版本与错误阶段，不能仅依据进程名称清理。
4. 普通会话归属记录新增可选的辅助角色标记；旧记录默认普通运行时，辅助记录保留生命周期证据并从普通写入归属中排除。
5. 助理保留现有持久化任务、历史和执行回执。新增字段按兼容默认值读取；旧协调器完成当前工作后，通过后继会话迁移到工具 revision 2。旧会话不会因工具更新而被中断。
6. CC Switch 数据库不迁移、不建表、不改字段，也不执行 checkpoint。用量数据只读，不与会话导入重复合计。
7. 助理消息库新增 `product_command_completions_v1` 完成记录，绑定已认证的发起设备、原命令 ID 和完整请求摘要。手机等待超时后，`commands/status` 可核对后台随后保存的成功结果；核对不会再执行任务。旧 Unknown 缺少这份证据时保持待恢复，不据此回填成功。
8. Android 的项目可写提示只采用当前连接上对所选项目的核验结果；撤权、来源变化和重连立即使其失效。历史 `projectAuthorization` 保留为历史证明，不能恢复当前写入开关。

### 当前候选的升级限制

旧 0.6.6 桥接不能原子暂停原生桌面发起的新写入。后台检查点交接可以保留它继续运行，但不能据此宣称桥接也已更换为 0.7.0。完整 Setup 遇到原生桌面、桥接或受管 Host 仍在运行时会显示等待，不会强制结束这些进程。完成其版本切换需要在任务结束后正常关闭原生桌面，再完成安装并重新打开。安装版本、后台版本、桥接版本和功能就绪状态需分别核对。

新版桥接提供有时限的维护屏障和启动前写入屏障。独立更新协调器已接通空闲核对、准确进程关闭、带屏障重开、原生会话读取验证、持久化放行和失败回滚；界面退出不会终止协调器。单元测试与限定的真实 Bridge 进程测试已经覆盖这些协议，但完整候选的原生桌面重开与回滚仍需以随包验收表为准。

旧版安装没有更新公钥时，需要由可信本地安装器提供独立固定的公钥，并校验签名清单后建立本地信任；下载源不能自行引入公钥。新版安装会保留并验证已有信任，损坏的信任记录必须报告错误。该本地引导不会赋予旧 0.6.6 桥接自动停止原生桌面的权限。

## 恢复与回滚

- 更新失败时先查看“更新与修复”的当前阶段和后台就绪状态。内置交接流程保留前一可用版本、检查点及操作回执；只有身份和检查点验证通过后才能恢复写入。
- 不直接替换正在运行的 EXE，不删除控制目录，不从备份覆盖仍在执行的助理数据库。结果未知的发送应核对历史和回执，不重复发送。
- 受管 Host 的回答回执与命令回执使用独立接口和 ID 范围。旧 Host 不支持回答回执查询时，不能根据命令“未找到”、待处理数量或版本号推断回答未发送；保留原操作与诊断，不自动重发或强制重启有待处理请求的 Host。
- 候选版已接受新任务后，不能把更新前的数据库备份直接当作当前状态。旧版本无法读取新增状态时，应保留候选数据并使用兼容版本恢复；不以清空数据解决版本差异。
- 配对、配置、助理状态、附件元数据和命令回执必须一起保留。公开分享诊断前只使用应用提供的脱敏导出，不分享配置、私钥、配对二维码或原始状态库。

## 更新签名与发布边界

`windows-update-trust.json` 随 Windows 文件清单校验。`windows-update.json` 包含签名后的版本、有效期、完整清单与下载位置；仅持有公钥的客户端不能签发更新。

自动更新按清单逐个下载 Windows 文件。正式发布时必须使签名清单列出的每个文件都可通过指定 HTTPS 地址获取；只上传 ZIP 或 Setup 不足以提供该更新源。离线签名验证、公开下载、真实升级是不同验收项，应分别记录。

## 验收证据

候选包需附包含构建号的验收表，分别列明协议与状态测试、真实数据库核对、隔离 Windows 升级、MuMu 手机功能与截图。软件渲染截图不替代硬件玻璃效果验收；MuMu 结果不表述为物理真机结果。未完成项目应明确标记，不能用编译成功替代功能验收。
