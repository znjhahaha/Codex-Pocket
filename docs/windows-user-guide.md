# Codex Pocket：Windows 使用说明

0.6 面向 Windows x64。先确保电脑上的 Codex 能正常使用，随后安装 Pocket；模型账户与 API 配置继续留在电脑。

## 安装和升级

1. 下载 Release 中的 `codex-pocket-0.6.0-windows-setup.exe`，双击运行。安装仅针对当前 Windows 用户。
2. 安装后打开开始菜单中的 **Codex Pocket**。首次安装会创建这台电脑自己的配对身份；覆盖升级保留已有身份、设备授权和草稿。
3. 根据首页引导选择局域网或公网路线，点击开启连接。在“连接新设备”中生成二维码，手机扫码确认。

不要只复制 ZIP 里的单个 EXE。便携包依赖同目录的助手、桥接和完整性清单。便携包首次安装可使用 `windows-install.ps1 -Initialize -Apply`；这是开发及管理入口，普通用户用 Setup 即可。

已有 Codex 进程可能仍使用旧桥接。界面分别显示安装版本、运行版本和待生效状态。等待任务结束后正常退出 Codex，再从 Pocket 打开；安装不会强行终止任务。

缺少 WebView2、VC++ 运行库或 Codex 时，按安装提示处理。没有签署 Windows Authenticode，不能保证系统不出现未知发布者提示。

## 连接和托盘

- 关闭主窗口会留在托盘。双击托盘显示窗口，也可从菜单配对、暂停连接或退出界面。
- 开启“登录后启动”会启动助手和托盘，默认不弹主窗口。
- 暂停连接停止 Pocket 的连接服务；不会结束 Codex 中的任务。电脑休眠或离线期间手机保留缓存。
- 手机连接、原生运行时和当前会话分别判断，某一会话出错不等于需要重新配对。

## 接手方式

**跟随桌面**为默认方式。桌面未启动时，Pocket 使用已验证的启动入口打开 Codex；失败会说明原因，不静默改成 CLI。

独立 CLI 需明确选择。既有 CLI 会话可以交还桌面，运行中则排队等待任务结束。Pocket 只释放自己的订阅，并核对原生占用；其他 CLI 仍持有时不会删除锁文件或杀进程。切换期间不重新发送结果未知的操作。

## 局域网和公网

局域网发现仅广播电脑身份和连接端口，不广播授权密钥。手机仍校验配对证书。同一网络的防火墙需要允许应用的专用私有网络端口；不要直接关闭防火墙。

临时 Cloudflare 隧道不需要自己准备服务器。固定域名模式需要账户、域名和受限 API Token；授权在 Windows 中加密保存。临时隧道地址变化且旧路线不可达时，请重新扫码。

自建中转可通过设置中的 SSH 部署：输入已有服务器与域名、核对主机指纹、检查条件，再部署。默认 Ubuntu／Debian，使用独立目录和 Docker Compose 项目。其他服务占用 80／443 时不覆盖，使用手动反向代理接入。部署成功后还要核对助手及手机实际握手。

## 故障处理

- **安装版本已变化／状态目录重定向**：从 Windows 开始菜单打开当前安装，避免旧安装目录或旧隔离上下文。
- **会话被其他应用占用**：查看会话接手状态；等当前任务结束后交还，不要强删锁文件。
- **授权撤销**：重新生成二维码配对，不从备份恢复已撤销授权。
- **写操作结果未知**：先核对原生历史；Pocket 不自动重发。
- **旧图片丢失**：先尝试历史媒体恢复；原生历史也缺失时显示原图丢失。

诊断会保留具体失败阶段与编号。公网、实际 Windows 登录、手机硬件等验收情况见 [0.6 验收记录](V06-ACCEPTANCE.md)。

脚本安装、恢复原环境变量等管理操作请参考 [旧安装说明](windows-legacy-install.md)，操作前以当前脚本帮助和预览输出为准。
