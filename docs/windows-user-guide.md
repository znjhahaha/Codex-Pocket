# Codex Pocket：Windows 使用说明

0.6 面向 Windows x64。先确保电脑上的 Codex 能正常使用，随后安装 Pocket；模型账户与 API 配置继续留在电脑。

## 安装和升级

1. 下载 Release 中的 Windows Setup 安装器，双击运行。安装仅针对当前 Windows 用户。
2. 安装后打开开始菜单中的 **Codex Pocket**。首次安装会创建这台电脑自己的配对身份；覆盖升级保留已有身份、设备授权和草稿。
3. 点击“开启连接”。局域网自动检测，公网可选择 Cloudflare、自有服务器或暂不配置。完成设置，等线路与 Codex 就绪后生成二维码，手机扫码确认；日常优先局域网，不可达时回退到已配置的公网。

不要只复制 ZIP 里的单个 EXE。便携包依赖同目录的助手、桥接和完整性清单。便携包首次安装可使用 `windows-install.ps1 -Initialize -Apply`；这是开发及管理入口，普通用户用 Setup 即可。

已有 Codex 进程可能仍使用旧桥接。界面分别显示安装版本、运行版本和待生效状态。等待任务结束后正常退出 Codex，再从 Pocket 打开；安装不会强行终止任务。

从旧版升级时，原有监督进程也可能继续运行。当前开发安装器统一为 **Codex Pocket** 入口；在管理界面或托盘选择“打开 Codex”。连接诊断会分别显示安装版本、安装代次，以及各进程报告的版本和核验状态。若提示等待重启生效，请等任务完成后重新登录 Windows，再核验后台；安装成功本身不证明热更新成功。不要手动启动 `pocket-bridge.exe`。

助手、桥接和托盘来自同一个安装包，分别负责手机连接、原生会话接入与后台入口。分进程运行不代表需要分别安装或手动启动。检查升级是否生效时，看连接页的运行组件版本，不能只看界面底部的版本号。

缺少 WebView2、VC++ 运行库或 Codex 时，按安装提示处理。没有签署 Windows Authenticode，不能保证系统不出现未知发布者提示。

如果安装报错，请展开“显示详情”。新的诊断记录保存在真实用户目录下的 `CodexPocketDiagnostics/install`，文件名为操作 ID，包含失败阶段、具体 COM 调用、原始 HRESULT 和回滚结果。`E_FAIL / 0x80004005` 不代表一定缺少 WebView2。不要删除配对或从 Codex 的 MSIX LocalCache 复制旧配置；保留诊断后重试原安装包。安装器不会结束原生 Codex 或模型任务。

若核心已验证安装、但快捷方式或登录任务未能注册，结果为“已安装，系统集成待修复”，诊断状态是 `installed_incomplete`（退出码 2）。保留当前身份和配置，重跑同一安装包只修复待处理步骤。未知的任务状态会保留恢复日志，不盲目覆盖外部任务。升级协调器尚未具备实际后台的平滑交接适配时，显示“等待重启生效”；不能把协调程序已启动视为升级完成。

## 连接和托盘

- 关闭主窗口会留在托盘。双击托盘显示窗口，也可从菜单配对、暂停连接或退出界面。
- 开启“登录后启动”会启动助手和托盘，默认不弹主窗口。
- 暂停连接停止 Pocket 的连接服务；不会结束 Codex 中的任务。电脑休眠或离线期间手机保留缓存。
- 手机连接、原生运行时和当前会话分别判断，某一会话出错不等于需要重新配对。

## 接手方式

**跟随桌面**为默认方式。桌面未启动时，Pocket 使用已验证的启动入口打开 Codex；失败会说明原因，不静默改成 CLI。

独立 CLI 需明确选择。既有 CLI 会话可以交还桌面，运行中则排队等待任务结束。Pocket 只释放自己的订阅，并核对原生占用；其他 CLI 仍持有时不会删除锁文件或杀进程。切换期间不重新发送结果未知的操作。

## 局域网和公网

### 同一 Wi-Fi

1. 手机和电脑连接同一个路由器。局域网自动检测，公网可以选择“暂不配置公网”。
2. 确认自动检测结果并启用连接；只在检测失败或多网卡匹配错误时展开高级网络调整。
3. 点击防火墙授权按钮，按 Windows 的管理员提示完成授权。只允许 Pocket 的已配置端口和专用网络，不需要关闭整个防火墙。
4. 等待就绪提示，打开 Codex，再生成二维码。电脑监听已就绪不等于手机已成功连接，最终以手机连接成功为准。

### Cloudflare 临时连接

选择“Cloudflare 隧道”，点击开启临时公网连接，等待公网地址和实际就绪状态；配置已保存或进程已启动都不会直接显示成功。需要固定域名时打开高级连接设置。临时连接失败时检查电脑网络，重试或返回选择其他方式。

### 自有服务器中转

已有服务时填写 `wss://主机` 或带部署前缀的基础地址，例如 `wss://主机/pocket`；不要复制完整的配对地址或附带令牌。尚未部署时切到 SSH 部署，依次核对指纹、检查系统和端口、部署、使用此中转。没有服务器时无需选择这一项。

局域网发现仅广播电脑身份和连接端口，不广播授权密钥。手机仍校验配对证书。同一网络的防火墙需要允许应用的专用私有网络端口；不要直接关闭防火墙。

临时 Cloudflare 隧道不需要自己准备服务器。固定域名模式需要账户、域名和受限 API Token；授权在 Windows 中加密保存。临时隧道地址变化且旧路线不可达时，请重新扫码。

自建中转可通过设置中的 SSH 部署：输入已有服务器与域名、核对主机指纹、检查条件，再部署。默认 Ubuntu／Debian，使用独立目录和 Docker Compose 项目。其他服务占用 80／443 时不覆盖，使用手动反向代理接入。部署成功后还要核对助手及手机实际握手。

## 故障处理

- **安装版本已变化／状态目录重定向**：从 Windows 开始菜单打开当前安装，避免旧安装目录或旧隔离上下文。
- **尚无可用线路**：助手可能已经运行，但局域网暂不可用且没有配置公网。重新检测网络，或选择 Cloudflare／服务器中转；这不是配对身份丢失。
- **线路还未就绪**：保留当前设置，重新检查该线路。仅本地网关启动、临时域名出现或 SSH 文件上传成功，都不代表可以扫码连接。
- **会话被其他应用占用**：查看会话接手状态；等当前任务结束后交还，不要强删锁文件。
- **授权撤销**：重新生成二维码配对，不从备份恢复已撤销授权。
- **写操作结果待确认**：Pocket 在后台查询同一命令和原生结果，不自动重发。状态保留在对应消息或问题旁，可打开“查看状态”；不需要处理全局未核对弹窗，也不影响无关问题。
- **手机显示在线但目录更新失败**：连接与会话目录分别判断。缓存仍可阅读，等待局部重试，不要删除配对；返回首页不强制重新加载全部目录。
- **发现广播失败**：查看线路证据中的 `mdns_*` 阶段。监听可能仍有效，可使用认证配对信息内的 LAN 地址；只有手机证书与设备授权通过才表示业务会话建立。
- **图片读取失败**：先确认手机和电脑助手均使用同批更新，并在“安装与运行版本”核对实际助手代次。新版本支持读取正在追加的历史，临时失败后可在图片查看器中重试，重连也会触发重读；已下载的路径图片缓存可离线查看。单次读取失败不能证明原图丢失，不要删除配对或历史。
- **图片引用已失效**：手机会通过同一原生会话重新取得图片引用，自动重试有节流；点击图片可手动重试。助手或桥接仍为旧代次时，先等待任务完成，再按升级提示让对应组件生效。只安装 APK 不会更新电脑上的助手和桥接。
- **新建会话提示历史读取失败**：此错误与连接、发送结果分别处理。保留草稿和附件，使用“重新读取”获取当前原生会话；不要因为读取失败反复发送同一消息。诊断需记录电脑助手及桥接实际代次、会话标识和读取阶段，不能仅凭截图认定消息丢失。

诊断会保留具体失败阶段与编号。公网、实际 Windows 登录、手机硬件等验收情况见 [0.6 验收记录](V06-ACCEPTANCE.md)。

脚本安装、恢复原环境变量等管理操作请参考 [旧安装说明](windows-legacy-install.md)，操作前以当前脚本帮助和预览输出为准。
