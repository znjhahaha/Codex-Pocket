## 会话问题

- 会话菜单增加“复制会话链接”，使用原生 UUID 生成 `codex://threads/<id>`，离线和未发消息的会话也可复制。Markdown 正文支持明确链接和裸链接，使用会话图标；自定义链接文本保留。代码块保持文本。
- 点击链接只在当前配对电脑和来源配置档案中解析目标；校验原生 ID、归属和读取能力，迟到结果不会覆盖已切换的会话。失败保留草稿；不因点击而发送消息。未知链接执行有界目录查找，无法读取会明确提示。
- bridge 等待 initialize 成功与桌面 initialized 通知后才声明就绪；schema 就绪主动唤醒并通知 helper。helper 重新取得初始空能力，隔离替换连接和旧状态，手机不再依赖桌面先发送一条消息来刷新能力。
- 能力及时就绪使首次手机创建也能选择本机支持的 legacy 历史模式。只有原生明确报告尚未物化、且同线程元数据证明为空闲空会话时，才展示等待第一条消息；普通读取失败保持错误。旧分页会话的原生历史能力缺失没有被伪装为空内容。
- 恢复会话时按当前 schema 支持情况使用 `excludeTurns:true`，避免不必要的全文恢复。

链接范围：现有 Markdown 正文。用户消息的纯文本、自绘表格点击和 Android 系统级 URI 入口未在本次扩展。只有 ID 的链接无法证明来源电脑，目标过旧且超出有界索引时需先从列表同步。没有进行真实手机到桌面链接验收。

## 原计划的整合

- 个人助理接入长期协调与独立执行会话、任务/成果入口、设置与定时；接管等待原生停止结果，待答快照权威核对，项目写权限依据原生 sandbox policy 并在恢复/调度时复核。
- 手机助理复用原生逐题问答，保留选项、多题 ID 和敏感答案的内存处理；审批展示命令、路径和可识别的完整权限范围。未知权限不能在手机盲目批准；离线时在写命令记录前拦截操作。本地回答编码失败可修改重试，已派发但结果不明的回答仍保持核对状态。
- 用量页读取本机 CC Switch 数据，区分代理请求、会话补录、未知价格和统计覆盖，保持只读、有界查询。连接诊断显示实际路线绑定的 relay 元数据与 Pocket 组件版本，缺少证据时显示未知。
- P2P 接入 Rust/JNI 和 Windows/Android 构建，保留 TLS、认证和单写入口。修复过期同 ID 协商重用、换线超时与流控夹具；中继可用时不因未完成的迁移无限等待。
- Runtime Host 使用独立进程和依赖包；冷恢复通过允许的元数据核对，未知活动不被误判为空闲。构建与安装清单包含 Host 和 P2P DLL。
- 升级交接持有维护锁到恢复完成，核验真实控制健康、代次和回执，未知 release 结果不重发，恢复先前远控开关。桌面保留桥接重启提示与恢复失败诊断。
